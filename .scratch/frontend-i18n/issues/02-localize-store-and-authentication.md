# 02-localize-store-and-authentication

Status: done

## Parent

`.scratch/frontend-i18n/PRD.md`

## What to build

Make the public Store and authentication journeys bilingual. A visitor must be able to change the Interface Language from the public header, browse the landing page and Plan cards, select a billing cycle, enter checkout, and use login or registration in Vietnamese or English. Static UI text, empty/loading states, and local validation copy in these journeys must use translation keys; Admin-authored Plan and Region content and backend error details remain unchanged.

## Acceptance criteria

- [x] The public header exposes the reusable `VI / EN` selector and preserves the selected language on refresh.
- [x] All static Store, Plan-selection, checkout, login, and registration copy renders in both languages.
- [x] Date/time and VND values in these journeys use the shared locale-aware formatters.
- [x] Plan, Region, and other Admin-authored data are rendered verbatim in both Interface Languages.
- [x] API error details remain verbatim, while no newly touched static UI text is hard-coded in a component.
- [x] The strict TypeScript production build succeeds.
